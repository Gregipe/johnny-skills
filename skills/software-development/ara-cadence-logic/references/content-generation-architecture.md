# Cadence Message Content Generation Architecture

## Context

ARA's outbound cadence engine sends WhatsApp, email, and call messages to leads on a schedule. How the *content* of those messages is authored and generated is a separate concern from the scheduling mechanics (timing, channel, stage gates). This document captures the design discussion from May 26, 2026, with subsequent refinements.

## The Two Approaches

### Approach A: Field-by-Field (Deprecated)

Each step stored structured fields per channel. At send time, fields were concatenated and `{{variables}}` interpolated. _This has been replaced by the NL prompt approach (Approach B)._

**Data shape (legacy):**
```json
{
  "steps": [
    {
      "channel": "whatsapp",
      "day": 0, "delay": 0,
      "fields": {
        "opening": "Hey {{first_name}} — saw {{company}} is expanding in {{city}}",
        "value": "Hunar's voice AI handles initial screening autonomously",
        "cta": "Worth 2 min to see if it fits? 🚀"
      }
    }
  ]
}
```

### Approach B: NL Prompt + Built-In Channel Guide (Active)

Each step stores a single free-form natural language prompt. At send time, an LLM generates the actual message from:
1. A template-level **system prompt** (brand voice, guardrails, positioning)
2. The **step desc** (message strategy — what to say, how to position, channel-specific guidance, what CTA)
3. A **built-in channel guide** (hardcoded dict per channel — not user-configurable)
4. **Lead context** (industry, stage, source, name, company)

**Data shape:**
```json
{
  "systemPrompt": "You are Hunar.ai's outbound voice. ... Never use hyperbole. ...",
  "steps": [
    {
      "channel": "whatsapp",
      "delay_hours": 0,
      "repeat_count": 1,
      "interval_hours": 0,
      "desc": "Cold WhatsApp. Reference their recent growth/expansion. Lead with a specific compliment. Warm, direct, 2-3 lines. No formal salutations. Position Hunar as a force multiplier for screening. CTA: '2 minutes to see if it fits?'"
    }
  ]
}
```

**Channel options:** WhatsApp, Email, Call, and Text (stored as `sms` in the data model). See "Add Channel Dynamic Picker" in the main SKILL.md for how channels are offered in the UI.

## Tradeoff Matrix

| Dimension | Fields | NL Prompt |
|-----------|--------|-----------|
| **Output quality** | Stitched-together feel. Hard to build narrative arc. | Rich, flowing prose. Full control over emotional arc. |
| **Industry specificity** | Weak. Same opening field across fintech/manufacturing/healthcare. | Strong. Prompt can branch: "for fintech, emphasize compliance; for manufacturing, emphasize cost." |
| **Conditional logic** | Impossible. No branching per lead attribute. | Possible in prompt: "If lead is from SaaS, mention integrations; if services, mention scale." |
| **CTA integration** | Bolted on as its own field. | Flows naturally from the message body. |
| **Predictability** | High. You control each component. | Lower. LLM interprets the prompt each time. |
| **Cost per message** | Zero (no LLM call at send time). | ~$0.001–0.003 (varies by provider and length). |
| **Latency per message** | Instant. | ~2–5s per message (LLM generation). |
| **Reliability** | Works without internet/LLM. Static fallback in code. | LLM outage = messages stay pending. No degraded fallback (Greg's design choice). |
| **Iteration difficulty** | Low. Change a field, done. | Medium. Changing one nuance requires re-prompting. |
| **Governance (nonos, tone)** | Fields constrain naturally. | Must be encoded in the system prompt; LLM can drift. |
| **World-class content ceiling** | Low. Hard to write great copy in 3 boxes. | High. A great prompt produces genuinely excellent copy. |

## Final Architecture

### Two-Layer Prompt Hierarchy + Built-In Channel Guide

1. **Template System Prompt** — Written once per cadence type (cold/inbound/nurture). Contains brand voice, industry positioning, competitive differentiation, guardrails (nonos). Inherited by every step in that template. Dynamic slots: `{{industry}}`, `{{stage}}`, `{{source}}`, `{{company}}`, `{{name}}`, `{{city}}`. Generated by Ava at induction, editable by Greg.

2. **Step Desc** — Written per step. Specific message strategy: what to say, channel-specific guidance (e.g. "short and warm, 2-3 lines for WhatsApp"), personalization cues, and CTA. ONE textarea per step — no separate channel prompt field.

3. **Built-in Channel Guide** (hardcoded in `_generate_step_message()`, not configurable):
   - WhatsApp: "Short, punchy (2-3 lines max). Use emojis sparingly. No formal salutation."
   - Email: "Include a subject line. 3-4 paragraphs max. Professional sign-off with name. No emojis."
   - Call: "Provide talking points as a structured outline, not a script. 3-5 bullet points."

4. **Lead Context Injection** — Auto-injected at send time from the Lead model: industry, stage, source, name, company, city.

### Timing Model (replaces old day+delay)

| Field | Description |
|-------|-------------|
| `delay_hours` | First fire offset from lead creation (in hours) |
| `repeat_count` | How many times to send this step (default 1) |
| `interval_hours` | Gap between repeats (default 0) |

### At Send Time

LLM generates the exact message from (system prompt + channel prompt + desc + lead context + sequence position). **If LLM is unreachable → action stays pending.** No degraded fallback. Greg prefers no message over a bad message.

**Channel Options**

WhatsApp, Email, Call, and Text (stored as `sms` in the data model). All four are available via the dynamic Add Channel picker in the cadence builder UI — only channels NOT yet configured for the current cadence are shown.

### Ava's Role

At induction completion, Ava generates `systemPrompt` for all 3 cadences (cold/inbound/nurture). Each system prompt is tailored to the cadence objective and incorporates learned industry/positioning skills. Per-step channel guidance is handled by the built-in `channel_guide` dict in `_generate_step_message()` — Ava does NOT generate per-step prompts. On significant skill promotion, Ava regenerates system prompts (flagging Greg's manual edits for review before overwriting).

## Greg's Key Insight

> "A well-worded prompt with the option of a CTA would probably be a slightly better way to do this."

The insight is that a single NL prompt captures **strategy**, not just **content**. A field like "CTA: Worth 2 min?" is content. A prompt like "Lead with the scaling pain, position as force multiplier, then ask for 2 minutes" is strategy that the LLM executes with nuance per lead.

## Refinements (May 26, 2026 Session)

### Primary Goal Removed

The separate `🎯 Primary Goal` input box was removed from the cadence builder. The cadence objective is now written as the **first line of the system prompt** itself. The `objective` field in the data model is kept for backward compat but no longer has a dedicated DOM element.

### System Prompt Persistence Fix

Two bugs caused the system prompt to silently disappear on page refresh:

1. **Falsy migration check** (`!data[key].systemPrompt`) — overwrites a user's saved prompt with the default if the saved value is an empty string `""`. Changed to `=== undefined`.
2. **Missing on-change save** — unlike step descs and the goal input, the system prompt textarea had no `change` event handler writing to localStorage. Added one so edits persist immediately on blur.

### Channel Prompt Merged into Step Desc

In earlier iterations, each WhatsApp/Email step had a separate `channelPrompt` textarea for channel-specific guidance. This was **removed and merged into the step desc** — the user now writes everything (what to say + channel constraints + CTA) in a single textarea. The built-in `channel_guide` dict in `_generate_step_message()` handles channel formatting automatically at the LLM level.

**Default Templates: Exactly 3 Channels**

All three cadence defaults (cold, inbound, nurture) now have exactly **WhatsApp, Email, and Call** as their three steps. An extra WhatsApp step was removed from cold. Text (SMS) is available as a 4th option via the dynamic Add Channel picker.

### Repeat Context for Multi-Send Steps

Each step can have `repeat_count > 1` paired with `interval_hours`. When a step fires multiple times, the LLM must differentiate send 1 of 3 from send 3 of 3. Two mechanisms handle this:

1. **Payload fields:** `_schedule_cadence_for_lead()` stores `_repeat_idx` and `_total_repeats` on each ScheduledAction payload alongside `_step_index` and `_total_steps`.
2. **LLM prompt:** `_generate_step_message()` injects `"This specific message is send X of Y for this step."` when `total_repeats > 1`, plus the instruction `"Vary the content naturally from previous sends — don't repeat the same angle or phrasing."`

This lets the system prompt's sequence evolution logic (early=broad/curious → mid=specific → late=sharp/closing) apply within a multi-repeat step, not just across different steps. The same step desc produces different content for each repeat because the LLM knows which send number it's on.
