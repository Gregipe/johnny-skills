# ARA Induction Implementation — May 2026

This reference captures the detailed implementation patterns that emerged during the ARA prototype build. Use this as a template for future induction flows.

## System Prompt Template

The combined system prompt has two parts: a static base prompt (scoring rules, SAVE_SKILL format, module structure) and a dynamic context section injected at session creation:

```
[Base Prompt]
- 4 module descriptions
- SAVE_SKILL block format with examples
- Scoring rubric (strict)
- Module completion signal format
- "Better to save too much than too little"

[Dynamic Context — built from DB]
Current induction state for {company}:
- Skills saved: {count}
- Modules covered: {covered}/{total}
- Progress: [{name, covered, skills_count}, ...]

{module_instruction}
```

The `module_instruction` is generated by:
```python
next_idx = min(skills_state['covered_count'], skills_state['total_modules'] - 1)
next_module = skills_state['modules'][next_idx]

if skills_state['covered_count'] == 0:
    module_instruction = "Start Module 1: Proposition. Ask the first question."
else:
    module_instruction = f"The customer has completed {covered_count}/{total_modules} modules. Start with Module {next_idx + 1}: {next_module['name']}. Do NOT re-ask about completed modules."
```

## API Endpoint Convention

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/induction/chat/{tenant_id}` | GET | Render the induction UI page |
| `/api/induction/{tenant_id}/chat` | POST | Send a message, get response |
| `/induction/chat/{tenant_id}/state` | GET | Get current progress state |

**Lesson:** The state endpoint path must exactly match what the frontend JavaScript calls. A mismatch between `/induction/chat/{id}/state` (backend) and `/api/induction/{id}/state` (frontend) causes a silent 404 that makes skills appear "lost."

## Session Clearing

When changing the induction engine or system prompt:

1. Delete old `CoachingLog` entries: `db.query(CoachingLog).filter(CoachingLog.tenant_id == X, CoachingLog.feedback_type == 'induction').delete()`
2. Remove in-memory session: `INDUCTION_SESSIONS.pop(tenant_id, None)`
3. Skills in the `Skill` table persist across clears — they're the durable knowledge base

## LLM Skill Saving Format

The LLM must emit structured skill blocks that the backend parses:

```
===SAVE_SKILL===
{"category": "proposition", "key": "logistics_segment", "value": "For logistics companies like Blue Dart..."}
===END_SAVE_SKILL===
```

The key MUST be a lowercase_snake_case identifier unique within the category. The value should be a complete, specific fact — not a one-liner.

## UI State Flow

```
Page Load → loadState() fetches `/induction/chat/{id}/state`
          → updateUI(state) populates sidebar, progress bar, button text
          → overview panel shows module cards with progress
User clicks "Continue Induction" → startInduction() finds first incomplete module
          → switchTab(firstIncomplete) opens conversation panel
          → Welcome message generated in JS based on state
          → User types answer → sendMsg() → POST to API
          → Response shown → updateUI called again with new state
          → Skill-save toasts fire if any skills were saved
```

## Port and URL Convention

- Development server: `http://localhost:8766`
- Consistent port avoids conflicts with other local services
- Root URL `/` redirects to induction chat (for single-tenant mode)
- Full dashboard at `/dashboard`
