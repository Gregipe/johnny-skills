# Claim/No-Call Nudge & Confirmation Flow — June 15, 2026

## Problem
Voice-note proposals like "Shall I set a reminder? Sound right?" were generated by the LLM WITHOUT `[TOOL_CALL:]` blocks. Result: `is_data_modifying=False`, no ActionItem created, user reply "Yes" routed as fresh request → LLM hallucinated "Arun Matthew?" from polluted conversation history.

## Fix Architecture

### 1. `_claims_action_without_call()` — Expanded Regex Detector
Location: `server.py` ~line 5265

Now catches three categories:
- **Past-tense claims:** "I've updated...", "Sent the message..."
- **Future/proposal:** "Shall I set...", "I'll create...", "Let me add..."
- **Confirmation-seeking questions:** "Sound right?", "That work?"

Exclusions: "what can I do", read-only verbs ("look up", "check"), "let me know"

### 2. Nudge Prompt — Reworded (line 5056)
```
You claimed or proposed an action but issued no tool call, so nothing happened.
Add the correct [TOOL_CALL:] block. Phrase your response as a proposal the user
needs to confirm — use 'I'll...' or 'Shall I...' language,
NOT 'let me X now' or 'Done'. The tool call will NOT execute yet;
the user must approve it first.
```

### 3. `_build_pending_description()` — Tool Args → Human Text
Location: `server.py` ~line 5204

When `resp_clean` is empty after stripping markers, builds readable proposal from tool args.
Handles: set_reminder, set_cron, create_lead, update_lead, send_whatsapp, send_email,
update_lead_stage, update_deal_stage, create_deal, trigger_cadence, escalate_to_human,
cancel_scheduled, create_action + generic fallback.

Output: "Set reminder: Send pricing to Rajesh; Send WhatsApp to Rajesh Sharma"

### 4. `[TOOL_CALL:]` Stripping
Second regex pass: `r'\s*\[TOOL_CALL:\s*[^\]]*\]'` on `resp_clean` before building description.

### 5. Structured Summary in Confirmation Prompt
Every pending response appends what will happen:
```
⏳ Confirm? Reply yes/send to proceed:
You're right. I'll create that action.

Create action: Send pricing information to Rajesh
```

### 6. Voice Handler — db_response Fix
Line 9724: `data_resp.get("db_response", "") or data_resp.get("response", "")`.
