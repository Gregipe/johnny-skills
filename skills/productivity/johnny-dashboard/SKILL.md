# Johnny Dashboard

## When to Use

- Greg's dashboard needs serving, restarting, or its data.json refreshed
- Debugging why the dashboard won't render
- Extending the dashboard (new tabs, Phase 2 Gmail wiring)

Greg's personal Chief-of-Staff dashboard — a local, private web app where he supervises Johnny's
work instead of operating it. Design lineage: Muse (transparency, goals→plans, least privilege) +
Grok Bot (status→preview→takeover, structured cards) + elegant-web-design tokens (light canvas,
one accent #254F3D, SF/system font, no emoji, no decorative pills).

## Files

- `~/johnny-dashboard/index.html` — the app: design system + 5 tabs (Today, Tasks, Feed, Goals, Correspondence) + right-hand chat/activity pane. RARELY changes.
- `~/johnny-dashboard/data.json` — the living state. Regenerated by Johnny (daily cron + on demand).
- `~/johnny-dashboard/bridge.py` — chat bridge on 127.0.0.1:8411: POST /chat {tab,message} → `hermes -z "<scoped prompt>"` → reply. GET /chat/<tab>, GET /activity (entries + cron snapshot + busy), GET /health.
- `~/johnny-dashboard/activity.py` — checkpoint helper the -z agent calls: `python3 activity.py <kind> <text>` (kinds: work|agent|chat|system|done).
- `~/johnny-dashboard/serve.sh` — starts bridge (nohup) + static server http://localhost:8410, both bound to 127.0.0.1.
- `~/johnny-dashboard/gmail_connector.py` — Gmail API connector (gregipe@gmail.com, OAuth client "Johnny CoS", scopes gmail.readonly+gmail.compose). CLI prints JSON, never tokens: `profile` | `threads [N]` | `thread <id>` | `draft --to X --subject S --body-file F [--thread-id T]`. Run via `uv run --with google-api-python-client --with google-auth python3 gmail_connector.py <cmd>`. Tokens: `state/gmail_token.json` (chmod 600, gitignored); auto-refreshed and persisted on 401.
- `~/johnny-dashboard/oauth_setup.py` — one-time OAuth consent flow (InstalledAppFlow loopback); re-run if tokens are revoked.
- `~/johnny-dashboard/state/` — chat_<tab>.json transcripts + activity.json + gmail_token.json + oauth_client.json (gitignored).
- `~/johnny-dashboard/README.md` — runbook.

## Chat architecture

Each tab has its own chat. Every message = one real `hermes -z` run with the johnny profile: the bridge builds a system prompt from (1) that tab's data.json slice, (2) an anchored "GREG'S CURRENT MESSAGE" section containing the message that was JUST sent, (3) the last 3 earlier transcript messages demoted to context-only, (4) working rules: the current message IS the task (tab data + earlier chat are context, not to-do lists), post checkpoints via activity.py, stdout = the reply bubble, never fake results. CRITICAL invariant: run_hermes must pass chat["messages"] (INCLUDING the just-appended user message) into system_prompt — the original [:-1] stripped the current message, so every run answered the PREVIOUS message (the one-task lag). Bridge serializes with a lock (409 busy), 10-min subprocess timeout, CORS allows only the 8410 origin. Per-tab transcripts persist in state/chat_<tab>.json; the activity feed polls every 3s client-side; cron snapshot refreshes every 15 min by parsing `hermes cron list` (job-id [state] blocks with Name/Schedule/Next run/Last run lines).

## Serve / stop

- Start: `terminal(background=true, persist_on_release=true)` → `cd ~/johnny-dashboard && exec ./serve.sh` (a server — silent daemon, no notify). **persist_on_release=true is MANDATORY**: without it the static server dies with the agent session's process tree (gateway restarts, session end, compression) and Greg finds 8410 down hours later — the bridge survives only if it was started by an older persist. Both servers must survive agent lifecycle cleanup.
- Verify: browser_exec → navigate http://127.0.0.1:8410/ (curl from terminal can trip a consent gate in TUI — prefer the browser).
- Stop: `pkill -f 'bridge\.py'` — NEVER `pkill -f "python3 bridge.py"`: the live argv is `…/Python bridge.py` (no 'python3' token), so that pattern misses it and a stale process keeps answering /health, masking a failed restart (this caused the one-task-lag to survive several 'fixes', Oct 2026). After any restart, verify the OLD pid is gone and the NEW one owns the port: `lsof -nP -iTCP:8411 -sTCP:LISTEN`.
- Never background with `&` inside a foreground terminal command — the shell guard blocks it.

## Daily refresh procedure (cron contract)

1. Re-derive the briefing: attention = approvals/reviews needing Greg TODAY (≤4 items, honest); headline = one sentence.
2. Tasks: carry forward open ones, update statuses, drop stale, keep group field values exact (today|week|delegated|waiting).
3. Feed: add genuinely new items with REAL source URLs grounded via web_search; ≤12 total, drop oldest; every item needs takeaway + a "why" tied to one of Greg's 3 goals.
4. Goals: update progress %, metric, latest_note. Greg's 3 goals: LinkedIn 5K→100K · start a company in India · stay close to family.
5. Correspondence: LIVE since Oct 2026. Pull real threads with the connector (`threads 12`), triage into priority/suggested_action per the email-inbox-triage dispositions, set sample:false, drafts stay "" until Greg asks. Never fabricate senders. Email rules: Johnny may DRAFT replies (gmail.compose) but NEVER sends — sending is approval-gated by Greg. Flag anything security-relevant (password resets, login alerts, payment anomalies) at the top of the briefing.
6. Write data.json atomically (temp file + mv). NEVER touch index.html or serve.sh during a refresh.
7. Verify: JSON parses; open http://127.0.0.1:8410/ in browser_exec and confirm all 5 tabs render with data.

## Rules

- Real data only — Greg treats invented facts as the #1 trust-breaker. Label anything synthetic as sample.
- ARA is STOPPED (since 2026-10-03): never add ARA/Ava tasks, health checks, synthesis reviews, or attention items to any refresh unless Greg explicitly says ARA is back.
- WhatsApp is the active owner channel: Johnny answers Greg in his Message Yourself thread (self-chat mode). No ARA sidecar exists anymore.
- No emoji anywhere in the UI or data.
- Deliverable = working artifact: after a refresh, open the page in the browser and confirm tabs render.
- Local-only: never deploy this dashboard publicly (email/tasks are private).
- UI edits: patch targeted anchors in index.html, never rewrite the whole file (risk of silently dropping a section).
